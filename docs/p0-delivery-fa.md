## ۴. الگوریتم دست‌دوم

۱. مشخصات فقط از متن و کاتالوگ تأییدشده خوانده می‌شوند؛ مقدار نامشخص حدسی تکمیل نمی‌شود.

۲. هویت مقایسه شامل برند/مدل استاندارد، تیپ، گیربکس، سال و تقویم، وضعیت خودرو، بازه کارکرد، وضعیت بدنه ساختاریافته در صورت وجود و روز تهران است. گیربکسی که در تیپ مشخص است بی‌دلیل دوباره در کلید تکرار نمی‌شود.

۳. سال نامشخص و تیپ نامشخص گروه مستقل دارند. سال یا تیپ متفاوت وارد میانگین یکدیگر نمی‌شوند. تقویم تبدیل نمی‌شود.

۴. بازه‌های کارکرد همان `1-50000`، `50001-100000`، `100001-200000`، `200001-300000`، `300001+` و `unknown` هستند. ضریب افت سال یا کیلومتر اضافه نشده است.

۵. بازنشر یکسان با Fingerprint متن استانداردشده کنار گذاشته می‌شود؛ لینک و شناسه ناوبری تلگرام وزن جدید ایجاد نمی‌کند. از هر کانال، آخرین آگهی معتبر همان گروه و روز یک رأی دارد.

۶. نمونه معتبر تنها، همان قیمت اولیه با `SingleSource` و اطمینان پایین است. چند نمونه پذیرفته‌شده، میانگین حسابی دارند؛ ۹۰۰ و ۹۴۰ میلیون برابر ۹۲۰ میلیون می‌شود.

۷. بررسی مقاوم از حداقل پنج نمونه مستقل آغاز می‌شود. حد تشخیص برابر بزرگ‌ترِ `3.5 × 1.4826 × MAD` و ۲۵ درصد Median است. این اعداد قابل تنظیم‌اند و روی داده واقعی بازار این پروژه کالیبره نشده‌اند. گروه بسیار کوچک، به‌تنهایی مبنای حذف آماری قرار نمی‌گیرد.

۸. حدود پیش‌فرض مبلغ نرمال‌شده ۱۰ میلیون تا ۱۰۰ میلیارد تومان است و قابل تنظیم است. مبلغ خارج از محدوده به بررسی می‌رود. ریال به تومان تبدیل می‌شود؛ محاسبات پولی decimal هستند.

۹. روزهای متفاوت مستقل‌اند. تاریخچه نهایی به‌صورت خودکار باز نمی‌شود و روز قدیمی قیمت روز جدید را بازنویسی نمی‌کند. اصلاح مستند مدیر می‌تواند گروه مرتبط را برای بازمحاسبه مشخص باز کند.

۱۰. Car.ir در این محاسبه وارد نشده است.

## ۵. الگوریتم مستقل صفر

- همان منابع تأییدشده استفاده می‌شوند، ولی تفکیک پیام، اعتبارسنجی، اجراها، جدول آگهی و گروه قیمت صفر مستقل‌اند.

## ۹. زمان‌بندی، تکرار و گزارش اجرا

- دریافت: `Telegram:CollectionIntervalMinutes = 300`؛ هر دو سرویس همین تنظیم را می‌خوانند.
- تیک بررسی دست‌دوم: `Telegram:CalculationIntervalSeconds = 60`؛ تیک به معنی محاسبه کامل نیست.
- صفر بعد از ورود داده، درخواست مدیر یا تغییر تنظیمات/کاتالوگ محاسبه می‌کند؛ بررسی دوره‌ای تازگی نیز باقی است.

- خطای یک کانال باعث حذف منابع یا توقف دائمی بقیه نمی‌شود. ثبت گروهی به خاطر اشغال موقت قفل صف، بقیه منابع را رها نمی‌کند؛ Pending پایدار توسط بک‌اند دوباره پیگیری می‌شود.
- Job دست‌دوم زمان، مدت، پیام جدید، تعداد استخراج، پذیرش/رد، دلایل و گروه‌های قیمت را ثبت می‌کند. شمارش پایان‌یافته با تغییر بعدی اعتبار آگهی بازنویسی نمی‌شود. برای اجرای قدیمی فاقد شمارش، عدد ساختگی نمایش داده نمی‌شود.
- Import مستقل صفر شمارش‌ها، دلایل، وضعیت ادامه و زمان اجرا را نگه می‌دارد.

## ۱۲. محدودیت‌ها و ریسک‌های عملیاتی

- علت رخداد مشخص «ارتباط با سرور برقرار نشد» در استقرار، بدون لاگ آن رخداد هنوز اثبات نشده است. لاگ جدید، Timeout، Redirect و خطای اتصال را قابل تفکیک می‌کند.
- قفل توزیع‌شده بر پایه SQL Server است؛ تست SQLite، اثبات رقابت چند Instance واقعی SQL Server نیست.
- تراکنش دریافت قدیمی هنوز می‌تواند دریافت شبکه را در بر بگیرد. این منطق قفل به‌صورت حدسی بازنویسی نشده است؛ اثر آن بر زمان قفل و نگهداری لاگ باید روی SQL Server واقعی اندازه‌گیری شود.
- مقادیر MAD، درصد اختلاف و حدود مبلغ باید روی داده واقعی تأیید شوند. وضعیت NeedsReview جایگزین حذف دائمی شده است.
- دسترسی به همه ۸۴ کانال عمومی یا قیمت دقیق Car.ir برای همه سال/تیپ‌ها تضمین نشده است. نبود داده معتبر، قیمت حدسی ایجاد نمی‌کند.
- بازنشر با تغییر عمده متن و بدون شناسه مشترک خودرو، همیشه از دو آگهی مستقل قابل اثبات نیست. یک رأی از هر کانال حفظ می‌شود؛ تشخیص‌های بیشتر نیازمند داده معتبر هستند.
- تست مرورگری و بازبینی واقعی موبایل/دسکتاپ هنوز لازم است. موفقیت Build جای آن را نمی‌گیرد.
- هشدارهای وابستگی‌های قبلی درباره `Microsoft.OpenApi` و `System.Security.Cryptography.Pkcs` در خروجی Restore موجودند؛ تغییر نسخه وابستگی خارج از اصلاح الگوریتم انجام نشده است.
- rollback مخرب Schema و پاک‌کردن تاریخچه/لاگ عملیاتی اجرا نشده است. Downها را بدون بررسی اثر بر داده و تأیید مالک اجرا نکنید.
